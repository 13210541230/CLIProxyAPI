02 · Authorize

添加 OAuth 账号

OAuth 账号从 CPA-Manager（18317）的 OAuth 页面添加和维护。Manager 连接 CPA（默认 8317）后可在一个面板完成授权、查看认证文件与配额；代理客户端仍使用 CPA 的客户端 API Key。

授权边界：只登录你有权使用的服务商账号，确认服务商的使用条款、配额和地区要求。CLIProxyAPI 不会授予订阅权限，也不会绕过服务商策略。

授权步骤

  1. 确认 Suite 已启动，打开 CPA-Manager 主面板：http://127.0.0.1:18317/management.html。
  2. 首次使用时完成初始化向导：CPA 连接地址填 http://127.0.0.1:8317，管理密码填 config.yaml 中的 remote-management.secret-key；可选的请求监控设置先保留默认值，点击登录进入面板。
  3. 从 CPA-Manager 导航进入 OAuth 页面，选择页面列出的服务商与登录方式，例如 Codex、Anthropic/Claude、Gemini CLI 等；具体选项以当前 Suite 版本为准。
  4. 点击对应的开始登录/授权按钮，在服务商页面登录并确认授权。不要把验证码、回调链接或凭据粘贴到公开聊天。
  5. 授权完成后回到 CPA-Manager 的 OAuth 页面查看状态；必要时在认证文件或配额页面确认账号已出现。其他账号逐个重复授权即可。
  6. 随后使用代理 API 地址 http://127.0.0.1:8317/v1 和 config.yaml 中的客户端 API Key 验证请求。

无法自动完成回调时

有些环境可以成功登录，但浏览器无法访问本机的 OAuth 回调地址。此时在浏览器授权结束后的地址栏复制完整回调 URL，切回 CPA-Manager（18317）的 OAuth 页面，粘贴到回调 URL 输入框并提交。提交后应看到授权成功状态或认证文件新增。

不要反复重新授权。先按页面要求提交本次完整回调 URL；它通常包含一次性 code/state，应视为敏感信息，在成功或失效后不要继续传播。

凭据存放在哪里

CPA 按 config.yaml 中的 auth-dir 管理 OAuth 认证文件。默认配置为 ~/.cli-proxy-api，即运行 CPA 的用户主目录下目录。更改运行用户或服务账户时，要同时确认该账户的配置路径和文件读写权限。

  • 不要把认证目录提交到 Git、放进网站可公开访问的目录，或附在普通故障工单中。
  • 备份应按凭据级敏感数据处理，限制可读人员并验证恢复流程。
  • 多个账号可以加入同一 CPA；实际选用哪个账号由请求模型、可用凭据和 CPA 路由策略决定。

验证模型与代理请求

先请求可用模型列表。Windows PowerShell 使用 curl.exe：

# PowerShell
curl.exe http://127.0.0.1:8317/v1/models `
  -H "Authorization: Bearer 替换为 config.yaml 中的客户端API密钥"

# Linux / macOS
curl http://127.0.0.1:8317/v1/models \
  -H 'Authorization: Bearer 替换为 config.yaml 中的客户端API密钥'

选用返回结果中的模型 ID，发起一条 OpenAI Chat Completions 示例请求：

curl http://127.0.0.1:8317/v1/chat/completions \
  -H 'Authorization: Bearer 替换为你的客户端API密钥' \
  -H 'Content-Type: application/json' \
  -d '{"model":"替换为实际模型ID","messages":[{"role":"user","content":"回复：连接成功"}]}'

成功收到上游响应后，客户端配置通常使用：

字段填写值
Base URLhttp://127.0.0.1:8317/v1
API Keyconfig.yaml 中的 api-keys 项
Model/v1/models 返回的模型 ID

示例以 Chat Completions 为例，不代表所有模型都支持该协议。若模型支持 Responses、Anthropic Messages 或 Gemini 协议，请使用相应端点与客户端配置。

遇到问题时

请求返回 401

检查请求头里的代理 API Key 是否来自 api-keys；它不同于管理密钥。

模型列表为空

确认 OAuth 已成功保存、凭据没有过期，并检查 CPA 日志中的账号/模型加载结果。

回调访问失败

保持授权页开启，复制最终回调地址并回到 OAuth 页面提交；不要重复点击授权直到确认状态。

Manager 无法登录或连接

先确认 18317 的 CPA-Manager 和 8317 的 CPA 都在运行；核对 CPA 地址、remote-management.secret-key 与防火墙设置。
