01 · Prepare

下载与安装

选择你们发布的完整 Suite 包。它将 CPA、CPA-Manager、更新器和启动脚本放在同一个目录，便于按版本配套运行。

发布源以你们的仓库为准：https://github.com/13210541230/CLIProxyAPI/releases。官方 Quick Start 可作为通用 CPA 安装参考，但本手册的 CPA-Manager 联合包来自上述 fork。

1. 选择 Release 资产

在稳定版 Release 的 Assets 中找以 CLIProxyAPI-Suite_ 开头的归档，不要用单独的 CPA 源码包替代。归档通常包含 CPA、CPA-Manager、cpa-updater、示例配置、启动/停止脚本和插件资源。

CLIProxyAPI-Suite_<version>_<platform>_<arch>.zip       # Windows
CLIProxyAPI-Suite_<version>_<platform>_<arch>.tar.gz    # Linux / macOS
资产标记选择建议
windows_amd64Intel / AMD 64 位 Windows
windows_aarch64ARM64 Windows
linux_amd64 / linux_aarch64分别对应 x64 / ARM64 Linux；要加载插件时选择支持插件的普通 glibc 包。
darwin_amd64 / darwin_aarch64分别对应 Intel Mac / Apple Silicon。

2. 校验下载文件

从同一 Release 下载 suite-checksums.txt，计算归档 SHA-256 并逐项比对。示例：

# Windows PowerShell
Get-FileHash .\CLIProxyAPI-Suite_<version>_windows_amd64.zip -Algorithm SHA256

# Linux
sha256sum CLIProxyAPI-Suite_<version>_linux_amd64.tar.gz

# macOS
shasum -a 256 CLIProxyAPI-Suite_<version>_darwin_aarch64.tar.gz

如果校验不一致，删除该归档并重新从指定 Release 下载；不要运行校验失败的动态库或程序。

3. 解压到稳定目录

将归档解压到专门的、运行账户可读写的目录，不要直接在下载临时目录或公开 Web 根目录启动。典型目录内容：

CLIProxyAPI-Suite/
├── cli-proxy-api[.exe]
├── cpa-manager[.exe]
├── cpa-updater[.exe]
├── config.example.yaml
├── start.bat / start.sh
├── stop.bat / stop.sh
├── plugins/                  # 支持插件的平台包
└── SUITE-README_CN.md

Windows x64 可用例如 D:\CLIProxyAPI-Suite；Linux 可用专用目录如 /opt/cliproxyapi，并确保运行账号可以写日志、认证数据及插件数据目录。

4. 创建并编辑配置

首次启动脚本会在缺少 config.yaml 时复制模板后继续运行。生产使用前建议先复制、编辑：

config.example.yaml → config.yaml

仅本机使用的最小配置片段如下；将它合并到模板中，不要删掉自己需要的其他配置：

host: "127.0.0.1"
port: 8317

auth-dir: "~/.cli-proxy-api"

api-keys:
  - "替换为足够长且随机的客户端API密钥"

remote-management:
  allow-remote: false
  secret-key: "替换为另一条独立的管理密钥"
  disable-control-panel: false
配置含义建议
host / portCPA 代理服务监听地址和端口。先绑定 127.0.0.1，默认端口为 8317。
api-keys客户端请求代理 API 使用的密钥。删除示例值，使用随机密钥；不要复用管理密钥。
remote-management.secret-key管理 API 和管理页面认证。设置独立随机密钥；留空时管理 API 不挂载。
remote-management.allow-remote是否允许非本机访问管理接口。本机部署保持 false；远程管理须另行做好网络隔离和 TLS。
auth-dirOAuth 凭据文件所在目录。默认在当前用户主目录下的 .cli-proxy-api；保护读写权限并备份。
不要直接公开默认监听：模板的空 host 表示监听所有网卡。局域网接入要同时配置防火墙；allow-remote 控制管理接口，不是代理 API 的监听开关。

4.1 账号与会话相关的必要配置

以下配置决定账号如何被选择、请求标识是否按账号改写，以及账号出口如何隔离；建议首次上线前一次配好：

routing:
  # 把同一会话绑定到同一账号，并在 TTL 内保持绑定，避免频繁换号
  session-affinity: true
  session-affinity-ttl: "2h"
  # 另一种满足 identity-confuse 前置条件的方式（也可保持默认 round-robin）
  # strategy: "fill-first"

codex:
  # 按所选账号改写 prompt_cache_key 与安装标识等请求标识
  identity-confuse: true
  # 默认 false：强制官方 UA 与 Originator；需要真实客户端指纹时再评估关闭
  disable-codex-cloaking: false

# 全局出口代理；单账号出口请在凭据文件里用 "proxy_url" 覆盖
proxy-url: ""

plugins:
  enabled: true
  dir: "plugins"
  configs:
    enterprise-access-audit:
      enabled: true
配置含义建议
routing.session-affinity把同一会话绑定到同一账号，并在 TTL 内保持。开启；TTL 按使用习惯设置（如 2h）。
routing.strategy账号选择策略。identity-confuse 只在 fill-first 或 session-affinity: true 时生效。按需；要用身份改写就确保两者之一成立。
codex.identity-confuse按所选账号改写请求标识，避免多机共用同一账号时标识完全一致。开启后抓一次上游请求确认真的生效。
codex.disable-codex-cloaking关闭对 UA 与 Originator 的强制伪装。默认保持 false；确需真实客户端指纹时再评估，并验证不会被上游拦截。
proxy-url全局出口代理；凭据文件中的 "proxy_url" 优先级更高。要一账号一出口时，把出口写在凭据文件里。
plugins插件总开关、目录与各插件配置。需要账号池、模型策略或审计能力时开启；账号池开关与并发上限由管理面板写入。
为什么这样配：各配置项与账号健康的关系、以及客户端侧配套（遥测关闭、时区、并发节奏）见配置与风控基线与风控预防速查。

5. 启动与停止

Windows

.\start.bat
.\stop.bat

也可在 PowerShell 指定配置：.\start.bat --config D:\cpa-config\config.yaml（将示例路径换成实际文件）。

Linux / macOS

chmod +x start.sh stop.sh
./start.sh
./stop.sh

指定配置：./start.sh --config /etc/cliproxyapi/config.yaml

启动脚本先启动 CLIProxyAPI，再启动 CPA-Manager，并记录本套件进程。正常停止请使用匹配的停止脚本，不要用进程名批量结束其他 CPA 实例。启动日志在套件目录的 logs/ 下。

6. 打开页面

页面默认地址用途
CPA-Manager（主操作入口）http://127.0.0.1:18317/management.html首次连接后，从同一面板管理配置、OAuth、监控、配额、更新和插件。
CPA 原生管理页（可选备用）http://127.0.0.1:8317/management.html仅在需要直接操作 CPA 原生管理接口时使用。

首次连接时，在 CPA-Manager 中按提示填写 CPA 地址及管理密钥；若改过 CPA 端口，连接地址也要相应调整。详见管理面板说明，OAuth 操作见OAuth 与调用验证。
