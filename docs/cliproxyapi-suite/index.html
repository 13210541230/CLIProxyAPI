Self-hosted AI gateway

从零搭建
CLIProxyAPI + CPA-Manager

从下载联合包开始，完成安全配置、OAuth 账号授权、API 连通验证，并了解 CPA-Manager 与 Enterprise Access Audit 的日常用法。

开始安装前往你们的 Releases
下载源说明：本手册部署的是包含 CLIProxyAPI、CPA-Manager 和 cpa-updater 的 CLIProxyAPI-Suite 联合包。请从你们维护的 13210541230/CLIProxyAPI Releases 下载；官方通用安装方式另见 CLIProxyAPI 官方快速开始，两者用途不同，不要混用发布包。

六步跑通

  1. 下载正确架构的 Suite 包。按 Windows/Linux/macOS 和 amd64/arm64 选择，再核对 SHA-256。
  2. 解压并配置。从 config.example.yaml 创建 config.yaml，替换管理密钥和客户端 API Key。
  3. 启动两个服务。使用 start.bat 或 start.sh，不要分别随意启动多个实例。
  4. 授权 OAuth 账号。打开 CPA-Manager（18317），完成首次连接后从面板进入 OAuth 页面登录。
  5. 发起真实请求。先访问 /v1/models，再用返回的模型 ID 发送一次聊天请求。
  6. 应用客户端基线。按 配置与风控基线 设置各用户机器的 ~/.codex/config.toml，并关闭客户端遥测与反馈上传。

服务关系与默认地址

组件用途默认地址 / 入口
CPA-Manager（推荐日常入口）管理 CPA 配置、OAuth、请求监控、配额、系统更新和插件资源http://127.0.0.1:18317/management.html
CLIProxyAPI接收 AI 客户端请求并路由到已授权上游账号http://127.0.0.1:8317
CPA 原生管理页（备用）需要直接访问 CPA 管理接口时使用；日常操作优先在 CPA-Manager 完成http://127.0.0.1:8317/management.html
安全起点：仅本机验证时把 CPA 的 host 设为 127.0.0.1、保持 remote-management.allow-remote: false。管理密钥与客户端 API Key 分开设置；公网部署前另行配置 TLS、网络访问控制与安全备份。
