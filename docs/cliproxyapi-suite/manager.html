03 · Operate

管理面板怎么用

本手册以 CPA-Manager（18317）作为日常管理主入口：初始化连接后，在同一管理中心完成配置、OAuth、账号运维、监控和插件操作。CPA 的 8317 是后端服务地址。

入口默认 URL主要职责
CPA-Manager（主入口）http://127.0.0.1:18317/management.html完成初始化后管理 CPA 配置、API Key、OAuth、认证文件、请求监控、账号配额、系统更新及插件资源。菜单依版本和启用功能略有差异。
CPA 原生管理页（备用）http://127.0.0.1:8317/management.html仅在 CPA-Manager 不可用或需要直接操作 CPA 原生页面时使用；日常讲解以 18317 为准。
首次使用 CPA-Manager：向导中填 CPA 连接地址（默认 http://127.0.0.1:8317），再填写 config.yaml 的 remote-management.secret-key 并点击登录。可按需启用请求监控，采集间隔首次使用保持默认即可。这里不能填客户端调用代理 API 的 api-keys。

日常功能一览

配置与 API Key

从配置页管理服务监听、认证目录、入站 API Key 和远程管理等设置；修改后按页面提示保存并让 CPA 应用配置。

OAuth 与认证文件

从 OAuth 页面选择提供商并完成授权；认证文件页可查看、筛选或按需导入凭据。日常授权无需切换到 8317 原生页面。

监控与配额

在请求监控查看请求量、模型、账号和用量信息；配额页查看或刷新已授权账号配额。展示维度以当前版本和采集设置为准。

系统与插件

系统页查看运行/版本信息并手动检查更新；已加载的插件可在插件资源入口打开，例如 Enterprise Access Audit。

CPA-Manager（18317）是本手册的主要操作界面。只有在 Manager 无法访问、某项高级管理操作未提供或需直接诊断时，才考虑使用 CPA 原生管理页（8317）或编辑 config.yaml；具体菜单名称可能随版本变化。

首次登录与运行检查

  1. 从 Suite 目录运行 start.bat（Windows）或 ./start.sh（Linux/macOS）；启动脚本会先启动 CPA，再启动 CPA-Manager。
  2. 直接打开主面板 http://127.0.0.1:18317/management.html。首次进入时按向导填写 CPA 地址和管理密钥，按需启用请求监控后提交登录。
  3. 进入后确认服务状态正常，并在 Manager 内打开配置、OAuth 或监控页面，避免把 8317 的原生管理页误当作 CPA-Manager。
  4. 若 Manager 无法连接 CPA，检查 CPA 是否运行、向导中的地址/端口是否对应 config.yaml、管理密钥是否正确及防火墙设置；查看 logs/ 下两项服务日志。

停止、更新与数据保留

停止时使用 Suite 配套的 stop.bat 或 ./stop.sh。脚本只针对该启动器记录的进程工作。

Manager 的“系统”页面主要用于手动检查版本并下载更新包，不等于自动安装。通过 Suite 启动两个服务后，可在套件目录执行：

# Linux / macOS：只检查版本
./cpa-updater --check

# Windows PowerShell：只检查版本
.\cpa-updater.exe --check

# 自动下载校验、安装并重启（按系统选择对应命令）
./cpa-updater
.\cpa-updater.exe

更新器会校验联合发布清单中的 SHA-256，并在更新流程中保留用户配置、认证数据、数据库、日志和插件设置；建议仍在升级前自行备份重要数据。

不要混用版本：CPA、CPA-Manager、更新器与动态库应来自匹配的 Suite Release。单独替换其中一个组件可能导致管理协议或插件 ABI 不匹配。
